# SigMark 后台：设计讨论稿

该文档保留面向正式部署的设计目标。当前内网试验版使用同一局域网地址、服务端设置批次、App 主动上传、管理台以令牌登录；不签发邀请码。正式公网鉴权、SSO 和持续采集仍未实施。实际边界见 [内网试验手册](LAN-PILOT.md)。

## 建议方案

优先用 **Go + chi、PostgreSQL、React + TypeScript + Vite、Docker Compose**。Go 提供单体 API，PostgreSQL 用关系字段支持筛选及聚合，用 JSONB 保存经校验的版本化报告；管理台和 API 建议同源部署。首版不加 Redis、消息队列或独立分析仓库。若更重视快速搭建管理员 CRUD，可选择 Django + PostgreSQL，先用 Django Admin，等专用报告界面稳定后再拆前端。

| 层 | 首期职责 |
| --- | --- |
| Android | 用户预览并主动提交脱敏报告和可选反馈；明确目标服务和提交状态 |
| Ingest API | 客户端使用短期、限范围上传凭证；按版本和字段白名单验证，限流、请求体大小限制、幂等；响应报告编号 |
| 数据层 | 报告、反馈、测试批次、审计事件；报告使用随机 ID，不用设备指纹做主键；索引报告时间、批次、Android 版本和默认网络类型 |
| 管理台 | 概览采集覆盖率 → 筛选报告 → 按来源查看字段和状态 → 同批次对比；按机型/ROM/API 查看受限比例及网络分布 |

建议把 **管理员与客户端身份分开**。管理台优先走组织已有 OIDC，区分维护者与只读分析者；报告查看、导出、删除有审计，外网部署需要 TLS 和合法域名。测试手机不保存全局共享密钥。

## 数据契约与最小化

- 默认允许机型/系统版本、网络类型/标准、信号或频率桶、字段状态和原因码；不原样上传完整本地 JSON。默认排除构建指纹原串、SSID/BSSID、IP、小区/订阅标识、精确位置及细粒度小区频点。用户反馈文本需提醒勿填个人信息，首版暂不接收附件。
- API 请求建议含 `schemaVersion`、`capturedAt`、短期测试批次、白名单字段和可选说明。时间保留客户采样与服务端接收两套；分析不将 App 视角当物理设备真值。
- 试点可设报告自动保留 30 天、管理员可按报告/批次删除；备份也纳入保留策略。不把报告内容或访问凭证写入访问日志。
- 第一阶段先用合成样例验证接口与报告页面，第二阶段接入内网显式提交；后台定时上传和外部部署要另行确认。

## 待决事项

1. 首期只部署在内网测试，还是需要外网团队访问？建议先内网。
2. 只要手动反馈式提交，还是确实需要连续观测和跨次关联？建议首版手动提交，以测试批次关联，不建立长期设备身份。
3. 管理员是否已有 OIDC/统一身份？如果没有，先决定管理员登录与账号运维方案，再定实施范围。

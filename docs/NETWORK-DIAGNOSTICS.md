# 网络诊断与隐私

本版在打开 App、授权返回或手动刷新时读取系统已经知道的网络信息，也支持用户主动启动前台链路记录；不发起 Wi‑Fi 扫描、测速或后台定位，不在后台定时采集。Debug 内网试验版可手动预览并提交独立的最小化报告；Release 仅本地采集与导出。权限授权与报告提交分开，授权不触发上传。

| 类型 | 采集范围 | 采集条件 |
| --- | --- | --- |
| 默认网络 | 活跃传输类型、互联网验证、计费、门户、系统估算带宽、IPv4 / IPv6 默认路由类型、专用 DNS 状态（API 28+）、链路 MTU（字节） | 普通 `ACCESS_NETWORK_STATE`。MTU 优先取 `LinkProperties.mtu`，其缺失时读取同一活跃链路的 `NetworkInterface.mtu`。值不可见时保留来源和状态 |
| Wi‑Fi | 当前主链路的频率（MHz）、频段、信道、RSSI（dBm）、协商速率、标准与安全类型 | Android 公开连接接口；默认网络须包含 Wi‑Fi。ROM 未上报则如实标注 |
| 蜂窝 | 默认数据订阅的注册运营商、SIM 运营商、PLMN、漫游与数据状态、调制解调器信号等级 | TelephonyManager 公开接口；具体值取决于服务及 ROM |
| 蜂窝数据制式 | 如 LTE、NR、IWLAN | Android 13+ 使用普通 `READ_BASIC_PHONE_STATE`；此字段不因授权双卡诊断而扩大读取范围 |
| 蜂窝小区无线参数 | 已注册小区的制式、LTE/NR 频段、信道号、参考频率与信号 | 用户可选授予精确位置权限，且系统位置开关开启；手动刷新时尝试公开小区更新，其余读取缓存；不请求 GPS，不导出小区 ID 或邻区列表 |

系统可能在 VPN 下仅公开部分默认路由信息。蜂窝订阅信息即使在 Wi‑Fi 上也可以存在，和默认路由分开展示；小区缓存是设备视角，未归属到独立 SIM，5G NSA 的辅小区不保证上报。Wi‑Fi 安全类型指当前连接协商的类型；Wi‑Fi 7 多链路场景不展示所有链路。

报告不采集 SSID/BSSID、MAC、IP、坐标、电话号码、IMEI、IMSI、SIM 序列号或用户账号。Android 将小区无线参数视为可能用于推断位置，因而要求精确位置权限。用户可拒绝，基础采集照常运行。JSON 含设备构建信息及运营商/无线参数，分享前请检查内容。

内网上报在预览中可展开查看白名单参数，包括实际 Wi-Fi 频率、信道、信号和协商速率，以及蜂窝制式、频段和信号等非标识参数。构建指纹、运营商名称及代码、精确小区信道/频点、坐标和小区标识仍只在适用的本地流程中处理，不进入上报。手机不使用邀请码或管理员令牌；服务端默认长期保存报告，不做自动过期清理。内网 HTTP 仅用于受控测试，传输不加密；远程部署前需改用 HTTPS。

0.15 上传预览可选「关联到同一设备资产」。默认不勾选，确认上传后仅向配置的 LAN 地址发送该安装对此地址生成的随机 UUID，服务器只保存其摘要；不采集 IMEI、序列号、MAC、Android ID，也不将随机标记写入报告正文、导出或时间线。勾选决定可以修改，取消后只停止后续关联。卸载、清除数据、刷机或改变接收地址可能产生新的标记。标记只用于归组，不是认证凭据或硬件身份证明。已关联记录由仓库管理员维护，可能长期保留。

0.16 的「指纹安全」是配置证据分析，不采集生物指纹。上传预览增加两项：系统是否配置锁屏凭证、系统报告的存储加密状态；仅在确认上传时发送，不读取凭证内容。强生物识别可用性、配置摘要、APK 签名摘要和虚拟设备标记仍仅本机展示或本地导出。见 [指纹安全](SECURITY-EVIDENCE.md)。

LTE 下行参考频率按常见频段的 EARFCN 区间换算；未内置的区间仍显示原始信道号而不推测频率。5G NR 使用 NR-ARFCN 全局栅格得到参考频率，不等于频谱测量。频段与带宽是否可用取决于系统返回；2G/3G 不推测 MHz。导出的完整 1.x 结构不变，部分字段新增可选 `reason`。

0.9 新增 EARFCN 到 LTE 下行频段的回退。优先使用 Android 回报的频段。Android 10 等缺少频段接口的设备可用已回报的 EARFCN 按 3GPP 表换算，详情显示实际来源。小区信道宽度仍取自系统公开的调制解调器样本。

0.12 在精确位置许可已授予且位置开启的情况下，尝试从 `TelephonyManager.serviceState.cellBandwidths` 获取载波带宽列表。系统返回有效列表时作为独立补充字段 `cellular.carrierBandwidths` 归档。这是默认数据订阅的带宽列表，可能涵盖多载波，与单一小区宽度不是同一参数。

0.13 报告分别展示默认网络、应用可见链路、Wi-Fi 的默认或非默认角色、SIM 逻辑卡槽状态、订阅数据状态和注册小区制式。Wi-Fi 与蜂窝可能同时可见；即使只看到默认 Wi-Fi，也可能有已就绪的 SIM 和已注册的 LTE 小区。没有可见蜂窝链路不等于无 SIM。只归档卡槽状态，不读取 SIM 标识、号码或账户。Android 10 的注册小区仍需要精确定位权限；它不等同于默认订阅的数据制式。

### 0.14 双卡与链路切换

- `cellular.defaultDataSlot` 是默认移动数据订阅的逻辑卡槽（界面从 1 起算）。Android 10+ 优先使用 `SubscriptionManager.getSlotIndex`；Android 8–9 使用可见活动订阅，在授权电话状态权限后尝试匹配。
- `cellular.slotService` 是各可见活动订阅的服务状态。Android 9+ 在用户选择「授权查看各卡状态」、授予电话状态和精确位置权限且开启位置后尝试读取。空卡槽继续由 `cellular.simState` 表示；有服务不等于蜂窝数据已连通。内网上报仅含逻辑卡槽和状态，不归档订阅 ID、SIM 标识、号码、账户或逐槽运营商。
- 在 App 点击「链路切换记录」手动开始；最多 60 秒或 120 条，不切换网络、不发额外网络请求。记录默认链路类型、系统联网验证与 Android 12+ 可见时的 Wi-Fi RSSI（dBm）。时间为启动后经过的毫秒数；连续相同状态合并，短暂失联可能被合并。离开前台即停止。可导出独立 JSON，不进入内网上报。

### 后续采集建议

1. **无线质量：** 补充 Wi-Fi 信道宽度、蜂窝信号随切换的变化和 LTE/NR 载波归属。仅在公开 API 能确认归属时关联。
2. **设备兼容矩阵：** 后台已支持按机型、系统版本和字段集计算去重覆盖，并按字段区分权限限制和系统未上报。后续加入两组 ROM 样本的并排覆盖比较，和可复用的真机复测清单。见 [后续路线](ROADMAP.md)。

Android 10+ 手动刷新会在有精确位置权限且系统位置已开启时调用一次 `requestCellInfoUpdate`；最多等待 2.5 秒，失败、超时或无注册小区时回退缓存。成功回调仍可能是缓存；小区字段展示系统采样年龄。如只读到 B3 等频段，会另显示标准下行范围；它不替代信道号、载波中心频率或配置带宽。移动数据开关、蜂窝数据连接、默认上网路由分别展示。

`RESTRICTED` 表示权限、系统开关或策略阻止读取；`UNAVAILABLE` 表示无适用数据或系统未回报；`ERROR` 表示读取异常。`errno=13 (EACCES)` 的 SELinux 节点与网络运行时权限无关，授权网络诊断后也不会改变。

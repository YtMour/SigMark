# 指纹安全：证据与限度

## 样本风险分级

后台「指纹安全」打开任意在库报告即可使用。规则 `sigmark-observation-risk/2` 按以下顺序给出单份报告等级：直接报告 Verified Boot 红色线索 → 红色；发现冲突或薄弱项 → 黄色；五项关键检查有未确认读数 → 灰色；否则 → 蓝色（本机观察，未独立验证）。五项关键检查为启动链、SELinux、锁屏、存储加密和系统补丁时效。虚拟标记、测试包可调试、旧报告缺项单独说明。绿色尚未开放。

新增辅助规则 `RUNTIME_ARCHITECTURE`：展开可同时核对印迹进程位宽、系统声明 ABI、内核报告架构。明确的 64 位进程与 32 位证据冲突仅提示复核；兼容的 32 位进程、翻译架构、未知 ABI、拒读与旧报告未归档均不等同于异常。三个来源都来自同一台设备的 App 观察视角，不是三个独立验证，也不据此判定实体、虚拟、修改或滥用。

解锁只在选中一条确已登记「预期解锁」的较早同资产基线时记为实验预期；临时 URL 开关本身不会降低分级。红色和矛盾读数不受实验预期覆盖。区别于独立的 `设备风险画像` 历史标签，分级只评估选中报告。导出 `sigmark.observation-risk/1` 含规则、触发项、采样时间和字段来源；不携带完整设备报告或额外标识。

## 0.21.0 · 厂商补丁的候选来源

Android 15+ 优先查询 `SecurityStateManager`。如果厂商补丁字段没有有效日期，或旧安卓没有此接口，只在当前 App 身份下读取固定属性 `ro.vendor.build.security_patch`。日期通过日历校验，来源仍写实际取得结果的接口。该值仅是 ROM 声明；不替代 `Build.VERSION.SECURITY_PATCH`，也不补写无法读取的 SELinux 实时模式。既有字段集 8 和白名单无需扩展。

## 0.20.0 · App 与 ADB 证据来源对照

在「指纹安全」选择原报告，打开「证据来源对照」，选择桌面观察文件。页面并排展示 App 与 ADB 的采样时间、来源和读数，独立验证标为「未执行」。操作者确认设备对应关系，型号不一致时有提示。App 拒读或旧报告缺项时会显示「缺少一方读数」。两份值均可比较且不同，先核对采样时点。

当前脚本写 `sigmark-adb-evidence/4`（`observer=ADB_SHELL`）；需要策略正文时可用 `sigmark-adb-evidence/5`（`observer=ROOT`，增加 `system.selinuxPolicy` 策略摘要，需 root）。在 v2/v3 的补丁、启动、SELinux、`ro.bootloader`、`ro.boot.veritymode`、`ro.debuggable` 与电池节点之外，增加 `ro.board.platform`、`ro.boot.hardware`、`ro.boot.hardware.sku` 三项身份声明，用于和 App 归档做同样的三对对照。读到才写值，读不到写 null；旧 v1–v3 文件继续可读；占位值 `unknown`/`null` 会被拒绝，按未读处理。

App 与 ADB 是两个观察身份，页面并列而不互填：App 拒读时 ADB 值只作对照，不写回字段、覆盖统计或风险等级。同一属性还可能被 ROM 按进程上下文改写——实测同一台 Pixel 6 上 App 读到 `corot-1.0.9`，shell 读到 `slider-14.5-12088207`，页面会提示「两值分别保留」。SELinux 的 App 值现在可能是带依据的推断，ADB 的 `getenforce` 是独立直接读取；两者一致时标为「App 为推断值，ADB 为直接读取」。

在仓库根目录执行下方命令，将设备序列号作为 ADB 连接参数。文件只包含型号、观察时间、少量固定只读属性、电池公开读数与驱动节点原值，以及 SELinux 模式；不含序列号、账号、应用清单或任意文件内容。文件停留在浏览器当前页面，切换报告或刷新后需重新选择。观察结果依赖手机当前的 shell 域和操作者选择的文件。

```powershell
pwsh -File backend/scripts/capture-adb-evidence.ps1 -Serial '<ADB 设备序列号>' -Output '.\app\build\adb-evidence.json'
```

字段集 8 的 Vulkan 声明版本、Camera2 按朝向及等级统计、传感器类型与唤醒数量用于 ROM 回归。相机只读应用可见的静态特性，传感器只读公开列表。上传预览包含三项摘要。图像、传感器轨迹、设备编号、单个相机 ID 和厂商自定义传感器 ID 均在这些摘要的采集范围之外。

## 仓库级身份分布

后台新增「身份分布」页（`#identity`），只读统计全库在库报告，回答三件单份报告回答不了的事：

- **多身份资产**：同一已归组设备的历史里出现过多套「型号 + 主板 + 硬件声明」。同一部位换过一次就列出来，按最近采样排序，最多 20 条。
- **跨资产同身份**：同一套声明出现在两台及以上已归组设备。同型号本来就会撞码，这里不判定克隆，只提供线索。
- **内部冲突报告**：同一份报告里 `Build.*` 与只读属性声明不一致（主板、硬件、SKU 三对）。两侧都有可用值才比较，受限或缺失不算冲突。

接口 `GET /api/admin/identity-summary`（规则 `sigmark-identity/1`）返回报告数、资产数、三个列表和冲突总数；列表超过上限时 `truncated=true`。页面可导出 JSON。它只读归档参数，不改变报告、资产关系或风险分级；身份声明不是物理设备认证。读不到的部分按“没有证据”处理，不会填成不一致。

报告详情打开时会在顶部显示「身份声明不一致」提示（只在该报告的三对声明里任一对两侧都有值且不同时出现），列出具体字段与两侧取值，并链接到全库身份分布。设备风险画像在 `identity_conflict` 命中时同样在顶部提示。这两处都只提示核对，不改变报告状态、风险等级或资产关系。

## 设备风险画像

后台打开「指纹安全」，选择一份报告即可查看；报告与资产的归组是用户/管理员显式建立的关系，不是物理硬件认证。同款手机不按型号合并。参考数美[设备风险画像接口](https://help.ishumei.com/docs/tx/deviceRisk/newest/developDoc/)对最近上报、历史标签和最近命中时间的区分。这里只解释 SigMark 仓库自己收到的证据；没有接入数美 SDK、运营商标识、商业风险名单、行为模型或交易数据。

| 规则（sigmark-profile/3） | 本次观察到 | 本次未见 / 证据不足 |
| --- | --- | --- |
| 虚拟环境声明 | 已归档硬件、产品或设备代号中有约定的虚拟构建标记 | 三项均有可用声明且不匹配才写「本次未见」；否则证据不足。同一系统声明不是三个独立证明 |
| SELinux 宽容模式 | 系统实时模式字段报告 Permissive，包括标明「推断」的值 | 明确 Enforcing 才算未见；策略拒读显示来源、状态和已有 errno。宽容不等于已关闭 |
| 调试器或内核跟踪 | 当前进程报告调试器已连接，或 `TracerPid` 非 0 | 两者都明确为否（`否` 与 `0`）才算未见。APK 可调试、开发者模式、无 SIM 都不作替代 |
| 注入与 Hook 线索 | 本进程映射或系统分区挂载出现约定代码（frida、gadget、xposed、substrate、riru、zygisk、lspatch、memfd_exec、overlay、magisk 路径等） | 两处都读到且为 `none` 才算未见；只代表本进程与当前挂载视图 |
| 可见的 Root 管理应用 | 可见的桌面应用包名命中固定列表（magisk、kernelsu、supersu、superuser、kingroot） | 读到 `none` 才算未见；受包可见性限制，未见不等于未安装 |
| 多用户 / 分身环境 | `userProfile` 为 `secondary` 或 `managed` | `owner` 才算未见。双开、分身与工作资料本身不是恶意结论 |
| ROM 验证与可调试声明 | `ro.boot.veritymode` 为 disabled/logging，或 `ro.debuggable` 为开启 | 两者都明确为 enforcing/关闭 才算未见。这是 ROM 自述，不是镜像校验 |
| DRM 密钥保护级别 | Widevine 报告 L3 | L1/L2 才算未见；L3 只表示软件级密钥保护，不等于模拟器 |
| 身份字段冲突 | 同一份报告里 Build 声明与只读属性声明不一致（主板、硬件、SKU 三对之一） | 至少一对可比且全部一致才算未见；没有可比对是证据不足。它只说明内部不自洽，不判定真伪 |

画像同时输出 `identityHistory`：同一资产采样前窗口里出现过的「型号 + 主板 + 硬件声明」组合，各带份数、最近采样时间与报告链接；组合不止一套时页面标为「出现 N 套」，提示先核对 ROM 或采样来源。它只是报告里的声明，不是物理设备认证。

每个标签另有 `historyRestricted`：历史样本中该标签的依据字段被系统拒绝读取（`RESTRICTED`）的份数。受限既不算命中，也不作为反证，所以不会把「读不到」当成「没问题」。当前报告自身的该字段恒为 0。字段集 17 之前的旧报告缺少新依据字段（如 `TracerPid`），这些标签在旧样本上显示「证据不足」，而不是「本次未见」。

这回答的是「这次采样看见过什么」，不是「使用者做过什么」。正常调试也会命中；没有命中不认证真机。对已有报告使用当前标明版本的规则按需计算，并非保存当时作出的结论；管理员调整归组或移入回收站会改变可见历史。

**下一轮实验（未实施）：** 由测试人员独立登记原厂实机、已知自定义 ROM 实机、已知模拟器三种参考环境，不从规则结果反推类别。同一环境测试普通启动/主动连接调试器、重复采样及切网；记录机型、ROM、采样数、规则版本和预期。按设备而非按上传次数报告命中、误报和证据不足；若两类实机都被当成虚拟设备，先修正规则。后续独立硬件验证从另一条证据链接入，而非给弱信号简单加分。

## 0.19.0 · 先确认要回答的问题

手机是实物、系统是预期镜像、曾发生危险操作，是三个不同的问题。当前版本在手机端提供安全配置与权限核对，**没有实施独立硬件验证或历史行为取证**。锁定声明、型号、配置摘要、临时密钥保护都不单独授予“原厂真机”结论；没有本机告警也不等于没有遭入侵。

| 检查面 | 当前依据与处理 | 不作何种结论 |
| --- | --- | --- |
| 启动与镜像 | 对照已读的启动颜色和两种锁定线索；红色优先处理，互相矛盾、解锁或自定义信任根提示核对；看不到标未确认 | 实验预期解锁不等于假机。绿色 + 锁定也只是本机声明 |
| 系统保护 | SELinux 直接读到宽容、当前用户未设安全锁屏、系统报告加密未启用，单独解释和给出行动；补丁按采样日（UTC）比较，超过 180 天提示查更新 | 受限不推断模式；补丁声明不是 CVE 测试；不评价其它用户的锁屏 |
| 特殊授权（自选、实时） | 单击后统计当前用户可见的已启用无障碍服务数、可读取窗口内容数、可执行手势数及两者交集；统计已激活管理员组件；只核对 SigMark 自身申请安装 APK 的授权 | 不读取窗口、执行手势或记下服务包名；不扫描所有第三方安装来源。授权存在不是发生盗读、遥控或安装；零条也不是全机清白 |
| 输入与保存 | 五项系统分析来自原快照；特殊授权有独立检查时间，仅在当前弹窗内。关窗不保留、不加入本地导出、LAN 白名单或统计；字段集仍为 7 | 特殊授权未运行与查到零项不同；旧报告不重建不存在的证据 |

### 同类方案：借鉴方法，不混用结论

- **GrapheneOS Auditor**：独立验证设备/服务进行首次配对，再观察同一设备是否更换启动密钥、系统或出现回退。首次配对并非证明整机历史清白。来源：https://attestation.app/about
- **Google Play Integrity**：将应用、设备完整性和访问风险分别返回；可控制输入或访问屏幕是能力信号。它的条件和白名单不等同于本地 Android API，对于实验室发行和无 GMS 的设备不把它当通行门槛。来源：https://developer.android.com/google/play/integrity/verdicts
- **Amnesty MVT**：分析经同意获取的取证材料，以入侵痕迹回答具体事件问题，不把普通授权当作行为证据。本版没有接入 MVT 或扫描私人通信。来源：https://docs.mvt.re/en/latest/

### 下一阶段：自定义 ROM 与原厂系统用不同验证策略（未实现）

1. 由管理员预先登记可信证明根和每种实验政策对应的启动公钥/预期镜像摘要；证明根认证的是密钥证明链，启动密钥识别的是镜像签发者，两种信任不要混淆。如果需要证明特定版本而不只是签发者，必须有相应镜像参考值和可验证的启动摘要。
2. 用户明确选择验证后，内网服务通过可信传输发出一次性限时挑战，把此次采样与应答绑定；在手机之外验证挑战、证书链的签名、有效期、撤销状态、硬件保护级别、设备锁定状态、受签名启动信息及预期应用身份。不用设备自己提交的信任根作为依据，也不把报告其他自述字段升级为已证明。
3. 分别返回「符合登记的原厂基线」「符合登记的实验 ROM」「与所选基线不符」「证据不足/设备不支持」「证明无效」。无服务、离线或缺少适用根，不自动判假。测试集覆盖原厂、已登记自签 ROM、未知根、过期/重放、证书撤销、采样错绑及 MI 8 不支持的路径。
4. 每个结果标明采样时间、验证时间、证据范围和策略版本。未经同意不上传证明链；不请求 IMEI、序列号或生物模板。若问题是“某天是否遭到操控”，另建用户主动授权的取证流程，不由此验证结果代答。

Android 验证指南：https://developer.android.com/privacy-and-security/security-key-attestation ；AOSP 证明字段：https://source.android.com/docs/security/features/keystore/attestation 。

### 0.18.2：给普通用户的检查与下一步

首屏先解释本机观察到什么、哪些状态没有公开、是否做过独立验证，技术字段点开再看。“指纹”指设备配置特征，不读取生物模板。TEE / StrongBox 描述的是那把临时测试密钥，不输出整机真假或安全分数。

- [GrapheneOS Auditor](https://attestation.app/about)：把被测设备与独立验证方分开，配对后可对照历史状态。可借鉴“首次建立基线 / 此后发生变化”的展示，但自定义 ROM 是否符合本实验的预期应另行标注。
- [KeyAttestation](https://github.com/vvb2060/KeyAttestation)：区分本机自测与把证据交给另一台设备验证。当前 SigMark 借鉴这个边界，不采集或上传证书链。
- 建议而非现有功能：用户主动发起独立验证，后端产生一次性挑战，校验证明链和撤销状态；未运行、设备不支持、验证失败和符合指定信任策略分别显示。参考 [Android 官方验证指南](https://developer.android.com/privacy-and-security/security-key-attestation)。普通采集与上传不依赖此功能。


字段集 7 扩展手动上传预览：系统公开的 ROM 分区构建指纹和时间、WebView 组件包和版本、系统/厂商声明补丁（API 35+）、SigMark 自身包名、渠道与签名证书 SHA-256，以及当前快照中主动运行的临时密钥保护测试结果。没有证书、公私钥、生物模板、硬件编号或第三方应用列表；未点击上传时留在本机。分区指纹描述软件构建，非设备唯一指纹。自测只问 Android 对该测试密钥的保护级别，不请求证明链或后台认证；刷新快照后需重新测试。

后台从已归档报告提取读数，App 面板从当前快照提取读数。两者都不读取生物指纹、密码或硬件唯一编号。「未进行硬件证明」独立于其它信号，资产归组也不是设备认证。

| 分析项 | 证据和判断 | 局限 |
| --- | --- | --- |
| 启动链 | ro.boot.verifiedbootstate、ro.boot.vbmeta.device_state、ro.boot.flash.locked。显式解锁、红色或来源冲突建议复核，黄色作为信任根线索 | 客户端可见属性，不是签名证明 |
| SELinux | system.selinux 的直接读数；辅以进程域显示 | 节点受限时不推定运行模式 |
| 补丁时效 | Build.VERSION.SECURITY_PATCH 相对报告采样日；180 天为实验复核阈值 | 不验证 CVE、补丁内容或厂商回移 |
| 保护状态 | KeyguardManager.isDeviceSecure 与 DevicePolicyManager.getStorageEncryptionStatus（字段集 6，新旧报告兼容） | 仅状态值，不探测密码质量、加密实现或指纹 |
| 调试 | ROM 构建类型、APK 可调试标志、当前进程是否连接调试器 | Debug 测试包不等于设备 Root |
| 配置一致性 | 核对同份报告的型号/API 头部与明细 | 两者来自同一 App 视角，非独立真伪证明 |
| 分区构建 | API 29+ 的 `Build.getFingerprintedPartitions()`；按分区名关联两次读数、UTC 构建时间 | 接口不列所有物理分区。仅新增/缺失的字段不判为 ROM 回退；构建指纹不是内容哈希 |
| 组件更新 | WebView 的当前提供程序、名称版本与内部版本号；API 35+ 额外读取系统、厂商 SPL | 同一提供程序内部版本号下降才提示复核。跨提供程序不比较数值高低；不推断漏洞或回移补丁 |
| 采集器签名 | 本机包名、渠道、版本名、内部版本号和**签名证书** SHA-256，同对应内网已发布记录比对 | 不是 APK 文件 SHA-256，不验证报告正文。登记之前的历史、未发布构建和其他渠道不拿最新版顶替 |
| 临时密钥保护 | 手动生成 AES 密钥，读取 `KeyInfo` 后删除；声明支持时尝试 StrongBox，暂不可用时注明使用默认提供程序 | 不要求 GMS。API 26–30 仅报告该密钥是否硬件保护；API 31+ 才细分级别。未手测、运行失败与软件保护并非同义 |

**复测建议：** 先保存新版本报告为基线；同机、同 ROM 不动配置再测一次，检查分区声明、WebView 提供程序和签名是否一致。然后做预期内的单项改动，比较对应证据。签名一致也不意味着是同一台设备；多台手机的相同 ROM 分区指纹可能完全相同。

**设计参考：** [AppVerifier](https://github.com/soupslurpr/AppVerifier) 的签名参照、[Auditor](https://attestation.app/about) 的独立验证角色，以及 Android 官方 [KeyInfo](https://developer.android.com/reference/android/security/keystore/KeyInfo) 和[硬件证明](https://developer.android.com/privacy-and-security/security-key-attestation)的不同含义。本版未集成第三方检测 SDK、Play Integrity 或在线证明服务。

查证时先展开原始证据，看字段来源、采样时间、状态和 errno。无读数显示「证据不足」，旧协议仅状态不会被当成实测。确需更高可信度时，另立证据通道：后端发一次性挑战、校验受信任证明链和时效、记录不可用原因；自维护 ROM 或没有相应服务的设备仍显示未认证。该路线尚未接入，公网前需先补 HTTPS 和上传身份认证。

## 两份报告比较

从顶部导航打开「指纹安全」直接选报告，或在资产列表用「安全分析」打开某份报告。选两份在库报告可直接进入比较；也可以在安全页内选基线，同资产最近在库样本优先列出。对照表显示两次读数、来源和缺失原因。未确认是同一资产时，只把结果当成样本对照，不把差异写成同一台设备发生了变化。

补丁日期倒退、连接调试器、SELinux 由强制到宽容、保护由启用到关闭都会建议复核。若是同一资产且该实验 ROM 预期解锁，可将一致的解锁线索标为「预期变化」；红色或相互矛盾的启动信号仍需复核。基线样本、当前样本和预期解锁选项可通过受管理会话保护的页面链接复现；选项不改写原始报告。

常用基线可命名保存，后续从「已保存的基线」复用。导出复测 JSON 包含稳定字段键、来源和结论枚举。详见 [ROM 回归工作流](REGRESSION-WORKFLOW.md)。

报告详情也可直接打开「缺项与补充证据」，查看非可用字段的复测条件及台架对照。见 [报告缺项与补充证据](SYSCALL-BOUNDARIES.md#报告缺项与补充证据)。

字段集 25：内核口径硬通道、overlay 多路径证据与设备画像 /8

采集（Android）
- 字段集 22：补第二观察通道 —— /proc/cpuinfo MIDR、sysconf、/proc/meminfo MemTotal、
  EGL 字符串。同一事实至少两条独立来源，任一被改写即可对照出来。
- 字段集 23：environment.overlayDeviceCodename 从 /proc/self/maps 里的框架 RRO 文件名
  取设备代号。RRO 文件名由构建期生成，改属性改不掉它。
- 字段集 24：cpu.cpuCapacity（内核每核算力权重，如 160/498/1024）与 memory.cmaTotal
  （内核预留连续内存池，如 652 MiB）。两条都是内核口径，不经 Build.* 也不经属性。
- 字段集 25：environment.overlayEvidence 把多路径证据串成一条
  rro:… / vendor_dir:… / product_dir:… / sku:… / soc:…；任一通道互相矛盾时追加
  conflict:<胜出通道>:<值>!=<通道>:<值>，让冲突本身成为可读证据而不是沉默。
- SafeReader 修一个真错：listNames 原先用 File.list()，它对「不存在」和「无权限」都
  返回 null，于是被拒的目录被报成「目录不存在」—— 把「读不到」当成「没有」正是伪装
  检测最不能犯的错。改为先 Os.stat：ENOENT/ENOTDIR → UNAVAILABLE/NODE_MISSING；
  stat 成功但 list() 为 null → RESTRICTED/ACCESS_DENIED（errno=13）；非目录单独记。
- 采集仍只用普通应用权限，AVAILABLE / UNAVAILABLE / RESTRICTED / ERROR 四态分开，
  不以 ADB shell 或特权读数冒充 App 可获得的值。

后台与前端
- LAN 契约升到字段集 25：单帧上限 259，词典 sigmark-lan-fields/16（235 条）。
- 设备风险画像 sigmark-profile/8：10 个标签，新增 hardware_declaration_conflict。
  判定用独立通道交叉：RAM 三源离散度、CPU 微架构是否落在声明 SoC 的核集合里、GPU
  家族别名、system.device 与 overlay 代号是否一致、以及「实测值恰好等于另一颗已登记
  SoC 的画像」这种反向识别。等于别的 SoC → 命中冲突；等于自己 → 确认；未登记 → 未知，
  绝不猜。
- SoC 登记表新增 sdm845（Snapdragon 845）：核 0x802/0x803、GPU adreno，按
  ro.board.platform 解析。capacity 与 cma 故意留空 —— 内核 4.9 不暴露 cpu_capacity，
  CmaTotal 是设备树值不是 SoC 常量，宁可空着也不填。
- Web 控制台新增 overlay-evidence 模块与冲突样式，档案页把 overlay 串与冲突原因渲染出来。

  需要可注入路径或卡死挂载点，当前测不了。
- qa_device_profile.py 的 --browser 分支与 --mobile-payload 真机 fixture 未在本轮跑。
